## 3. Findings separated by proof level

**Confirmed from v2.2.0 source:**

- NEW and ALL inline browser script snippets contain user-visible hard-coded English labels and many runtime status/error strings (`Check NEW`, `Download verified ZIP`, `Confirm receipt and advance NEW`, `Check ALL`, `Download ALL ZIP`). Those embedded strings are not consistently passed through WordPress gettext translation APIs, unlike many PHP settings labels. The shipped POT does not constitute a complete translation. **Candidate gap: translation-ready UI and RTL-language parity.**
- Each workflow currently inserts its own modest panel in the Gravity Forms Entries screen and uses native `button` classes and an `aria-live` status for result text. This supports some WordPress-native/accessibility direction; it is **not** evidence of comprehensive accessibility.
- The NEW acknowledgment control explicitly says the operator saved/checked the ZIP, and its coverage only advances on explicit ACK. ALL ignores filtered selection and NEW history. Preserve these safety semantics, even if copy/layout changes.
- The release engineering and substantive ZIP/NEW/ALL regression suite is already established; duplicating it as a separate generic framework would not improve the operator outcome.

**Not yet verified by the reported install or cited CI:**

- Operator independently understands which of four modes to choose, what first NEW run means, and the difference between browser SHA-256 confirmation, local retention and deliberate ACK.
- Real-use NEW initial snapshot → verified ZIP saved → manual ACK → later NEW; independent ALL repeated before/after NEW; meaningful recovery if ZIP cannot be retained.
- Persian/RTL strings and technical LTR isolation, keyboard-only focus order and post-action state, narrow-width/zoom legibility, screen-reader result feedback, and style/JS interactions with the Owner's installed Gravity Forms environment.
- Host-specific PHP/memory/time, large-file throughput, network interruption, remote/offloaded uploads and persistent object-cache configurations.

Do not turn the absence of these observations into claims of actual runtime defects.
